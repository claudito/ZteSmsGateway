Arquitectura Gateway SMS

Diagrama de red de la bandeja de notificaciones SMS y el segmento que se necesita para alojar el equipo que la corre.

La bandeja de notificaciones SMS corre en una PC Windows que expone una API HTTP (FastAPI, puerto 8000) hacia la red interna. Esa misma PC controla por USB uno o varios routers celulares ZTE MF920V, que son los que realmente envían el SMS a través de la red celular (con SIM propia cada uno).

Lo que necesitamos de Redes es un segmento (VLAN) para esa PC, con IP fija y el puerto 8000 alcanzable desde los sistemas que van a consumir la API. Las subredes que usan los routers por USB son privadas a esa PC y no requieren ningún cambio de red — se detallan en el diagrama solo para que quede claro que no son parte del pedido.

Solicitud a Redes

Cuatro puntos concretos para dimensionar el segmento — el resto del diagrama es contexto.

Segmento

VLAN dedicada para el host de la PC gateway, con IP fija (hoy la asigna DHCP genérico, lo que puede cambiarla).

Puerto

TCP 8000 entrante hacia esa PC, desde los sistemas internos que van a llamar a la API (a confirmar el listado exacto de origen con el equipo del gateway).

Protocolo

HTTP plano, sin TLS por ahora.

Mantener el tráfico dentro de la red interna — no exponer este puerto a internet.
Fuera de alcance

Los routers ZTE usan otro segmento (privado, vía adaptador USB/RNDIS) — 192.168.50.0/24, 192.168.51.0/24, etc., uno por router — precisamente para no chocar con la red corporativa.

No hace falta crear nada para ellas del lado de Redes.
